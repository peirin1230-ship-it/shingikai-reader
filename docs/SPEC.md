# shingikai-reader 仕様書 v0.3

審議会資料を、スライド1枚ずつ背景を含めて精読・注釈するためのリポジトリ。

- **リポジトリ名**: `shingikai-reader`
- **公開設定**: パブリック（GitHub Free）
- **最初の対象**: 社会保障審議会 医療保険部会 第215回（令和8年9月11日）参考資料「基礎資料」

### v0.2からの変更点

| 変更 | 理由 |
|---|---|
| 複数会議体に対応したディレクトリ構成に変更 | 医療保険部会以外にも広げる運用が決まったため |
| **原典PDFをコミットしない** | 公開リポジトリでの第三者著作物の再配布を避けるため（§7） |
| **スライド画像をコミットしない** | 同上、およびリポジトリサイズの長期抑制（§1.3） |
| GitHub Pagesへの配信をCI経由に統一 | 画像がGit履歴に入らない構成にするため |
| 出典表記・ライセンスの節を追加 | 公開運用に伴う整理（§7） |

## 0. 実物解析でわかったこと

### 0.1 対象資料の性格

第215回の議題は「①OTC類似薬の保険給付の見直しの実施について ②医療保険制度改革について」。今回入手したPDFはそのどちらの本体資料でもなく、**両方の議論の土台となる事実を並べた参考資料**である。

| 項目 | 実測値 |
|---|---|
| PDF総ページ数 | 83 |
| 表紙・目次 | 2 |
| 章扉 | 9 |
| **実質スライド** | **72** |
| ページサイズ | 780 × 540 pt（横向き） |
| ファイルサイズ | 6.6 MB |
| テキスト層 | あり（Meiryo/游ゴシック等が埋め込み済み） |

内容はおおよそ統計グラフ・数表が約45枚、制度の仕組み説明が約17枚、国際比較が約6枚、改革の経緯整理が約5枚。**論点提示や見直し案のスライドは1枚もない。**

### 0.2 これが設計に与える影響

基礎資料のスライドに固有の問いは、論点資料とは違うところにある。

> **この事実は、どの改革論点の論拠として持ち出されるのか。**

たとえばスライド34「年齢階級別一人当たり医療費と自己負担額」は単なる統計ではない。「70代以降は医療費が高額なのに自己負担が低く抑えられている」が太字下線で強調されており、高齢者の窓口負担引上げ論の直接の論拠になる。スライド69「家計の金融資産」は、金融所得の保険料への勘案（令和8年法律第31号で導入済み）を支える数字である。

したがって本システムでは、**基礎資料を事実データベースとして構造化し、そこから改革論点への逆引きを張る**（§2.3）。

### 0.3 テキスト抽出が効かない7枚 ★重要

`pdftotext` の抽出文字数を全ページ測定した結果、以下7枚は図表が画像として貼り込まれており、テキスト層がほぼ空だった。

| PDFページ | スライド番号 | タイトル | 抽出文字数 |
|---|---|---|---|
| 21 | 20 | 妊産婦死亡率・乳児死亡率の推移 | **2** |
| 24 | 23 | 医療費全体の伸びの要因～高齢化率との相関～ | 65 |
| 25 | 24 | 主要国の医療保障制度（概要） | **44** |
| 28 | 27 | 医療保険制度の体系 | 29 |
| 29 | 28 | 各保険者の比較 | **23** |
| 58 | 57 | 医療費の動向 | **20** |
| 59 | 58 | 医療費の伸び率の要因分解 | **38** |

問題は、このうち4枚（スライド24・28・57・58）が**この資料でもっとも数字の密度が高いページ**だという点である。「各保険者の比較」は保険者別の加入者数・平均年齢・一人当たり医療費・保険料をすべて含む一覧表、「医療費の伸び率の要因分解」は14年分×5指標の数表である。

これらの数字は画像から読み取るしかなく、**LLMによる数値の読み取り誤りが最も起きやすい**。§3のPhase 2でこの7枚を別扱いとし、§6で人間による突合を必須にする。

## 1. アーキテクチャ

### 1.1 リポジトリに何を置き、何を置かないか ★v0.3で変更

```
  ┌──── GitHub リポジトリ（パブリック）─────┐
  │  解説Markdown / 横断KB / スクリプト      │
  │  原典PDFのURLとSHA256（実体は置かない）  │
  └──────────────┬──────────────────────┘
                 │ GitHub Actions
                 │  ① 厚労省からPDFを取得（SHA256でキャッシュ）
                 │  ② 画像を生成
                 │  ③ サイトをビルド
                 ▼
        actions/upload-pages-artifact
                 ▼
        GitHub Pages（画像はここにだけ存在する）
```

| 種類 | コミットする | 理由 |
|---|---|---|
| 解説Markdown | ○ | これが成果物。差分管理の対象 |
| 横断KB（用語・年表・論点） | ○ | 同上 |
| スクリプト・ワークフロー | ○ | 同上 |
| PDFのURL・SHA256・取得日 | ○ | `manifest.yaml` として。再現性の担保 |
| **原典PDF** | **×** | 第三者著作物の再配布を避ける（§7）。`source/` は `.gitignore` |
| **スライド画像** | **×** | 同上。加えてGit履歴に入ったバイナリは削除しても残るため |
| ビルド成果物 | × | `dist/` は `.gitignore`。Pagesへはアーティファクトとして直接配信 |

Pagesのデプロイはブランチにコミットせずアーティファクトをそのままホスティングするため、この構成なら画像がGit履歴に一切入らない。

原典が厚労省サイトから消えた場合に備え、`manifest.yaml` にはWeb Archiveの保存URLも併記する。過去回の資料ページは長期間残る運用になっているため（平成29年の第108回のページも現存）、実際の消失リスクは低い。手元のアーカイブは `source/` にローカル保持すればよい。

**共有ナレッジベースがこの構成の最大の見返り。** 高額療養費・診療報酬・後期高齢者医療制度といった用語は医療保険部会でも中医協でも医療部会でも登場する。1回書けば以降使い回せて、「この用語がどの会議体のどのスライドに出たか」の逆引きが会議体をまたいで張れる。

**ID体系**: `{council}-{回}-{資料}-p{PDFページ3桁}` 。例: `hoken-215-sanko-p029`。

**ファイル名はPDFページ番号を使う。** スライドに印刷された番号ではなく、PDFページ番号で統一する。表紙と目次に印刷番号がなく、印刷番号を採用すると欠番が発生してソートが壊れるため。印刷番号はフロントマターに `printed_page` として別途持たせる。

### 1.3 サイズ設計

GitHubはリポジトリを1GB未満、できれば5GB未満に保つことを推奨している。1資料セット（約80枚）あたりの内訳は以下のとおり。

| 中身 | サイズ | コミット |
|---|---|---|
| 原典PDF | 約7MB | × |
| スライド画像（1600px WebP + サムネイル） | 約9MB | × |
| 解説Markdown（80枚 × 約6KB） | 約0.5MB | ○ |

**コミットされるのは1セットあたり0.5MB程度。** 年20セット処理しても年間10MB、10年続けても100MBに届かない。全部コミットする構成だと1セット16.5MBで年間330MB、3年で1GBに達していた。

Actionsのビルド時間はPDFをSHA256でキャッシュすることで抑える。パブリックリポジトリではActionsの分数に上限がないため、コスト面の制約はない。

## 2. データモデル

### 2.1 スライドファイル

#### フロントマター

```yaml
---
id: hoken-215-sanko-p029
council: hoken
meeting: 215
meeting_date: 2026-09-11
document: 参考資料（基礎資料）
pdf_page: 29
printed_page: 28
title: 各保険者の比較
chapter: 日本の医療保険制度
slide_type: 現状データ
themes: [保険者財政, 世代間負担]
terms: [市町村国保, 協会けんぽ, 組合健保, 後期高齢者医療制度]

origin: null                # 他会議からの転載元。転載でなければ null
data_source: 医療保険に関する基礎資料（令和5年度）
supports_topics: [高齢者負担の在り方, 保険者間の負担調整]

text_extractable: false     # §0.3 の7枚は false
third_party_figure: false   # ★図そのものが第三者著作物か（§7）

confidence: high
review_status: draft
number_verified: false      # 数値を人が原典と突合したか
---
```

`third_party_figure: true` のスライドは、ビューアで画像を表示せず出典リンクに差し替える。判断を後から一括で変えられるよう、パイプラインに焼き込まずフラグで持つ。

#### `slide_type`

| タイプ | 枚数目安 | 解説で重視すること |
|---|---|---|
| `現状データ` | 約45 | 出典・集計年度・母数・実績か推計か。**そして、どの論点の論拠になるか** |
| `制度概要` | 約17 | 現行制度の仕組みと、いつ・なぜその形になったか |
| `国際比較` | 約6 | 比較対象の選定意図、指標の定義差、単純比較できない点 |
| `経緯整理` | 約5 | 各改正の背景と、この整理表に載っていない改正 |
| `chapter` | 9 | 章の狙いと収録スライドの一覧のみ |
| `cover` / `toc` | 2 | 解説不要。索引としてのみ保持 |

論点資料（資料1・資料2）を追加する際は `論点提示` と `対応案` を加える。

#### 本文テンプレート

章扉・表紙を除く72枚に適用する。

```markdown
## 1. 一文要約
（40字以内）

## 2. 書いてあること
（図表・数字を漏らさず言語化。表はMarkdown表で再現。
  グラフは軸・単位・期間・系列を明記。ここは転記であり解釈を入れない）

## 3. このスライドの役割
（章の中での位置。直前・直後のスライドとの論理的つながり。
  転載スライドの場合は、元の会議で何を論じるために作られた図なのか）

## 4. 背景
### 4-1. 制度背景
### 4-2. 政策背景（骨太／改革工程表／法改正のどこから来ているか。日付必須）
### 4-3. 数字の背景（出典統計、集計年度、実績か推計か、母数、定義上の注意）

## 5. 用語
（1行定義 + kb/glossary へのリンク）

## 6. この事実が支える論点
（このデータが、どの改革論点の論拠として使われるか。
  スライド上の強調表示（太字・下線・赤枠）は、事務局がどこを読ませたいかの
  直接の証拠なので必ず拾う。kb/topics.yaml と相互リンク）

## 7. 数字の読み方の注意
（グラフの軸の切り方、比較対象の選び方、年度のずれ、
  この数字から言えること／言えないこと。
  同じ論点について別の切り口があるなら併記する）

## 8. 関連スライド
（同じテーマの他スライド、他会議体の類似スライド）

## 9. 出典
```

セクション6と7がこのシステムの付加価値の中核になる。

## 3. 生成パイプライン

### Phase 0: 取得（ローカル / CI 共通）

```bash
python build/fetch.py --council hoken --meeting 215
```

`manifest.yaml` のURLからPDFを取得し、SHA256を検証して `source/` に置く。`source/` はgitignoreされているので、リポジトリには入らない。審議会資料は訂正版に差し替えられることがあるため、ハッシュ不一致は警告として扱い、`manifest.yaml` に改訂履歴を追記する。

### Phase 1: 分解

```bash
pdftoppm -r 200 -png -f 1 -l 83 source/hoken/215/sanko.pdf work/p
cwebp -q 80 -resize 1600 0 work/p-NN.png -o images/hoken/215/sanko/p0NN.webp
pdftotext -layout -f N -l N source/hoken/215/sanko.pdf work/p0NN.txt
```

抽出文字数が100字未満のページには `text_extractable: false` を自動で立てる。今回は7枚が該当する（§0.3）。

### Phase 2: 一次解説の生成

**1リクエスト1スライド。まとめない。** 複数枚を一度に処理すると後半のセクションが埋まらなくなる。72枚を72回に分ける。

渡すコンテキスト:

| 入力 | 目的 |
|---|---|
| 当該ページの画像 | 図表の読み取り |
| 当該ページの抽出テキスト | **数字の正確な転記** |
| 前後2ページの抽出テキスト | セクション3を書くため |
| `_meta.yaml` の章構成 | 資料全体での位置づけ |
| `kb/topics.yaml` 全文 | セクション6の逆引き |
| `kb/timeline.yaml` 全文 | セクション4-2の年代整合 |
| 既存 `kb/glossary` の該当項目 | 用語定義の一貫性 |

**`text_extractable: false` の7枚は別プロンプトを使う。** 照合先のテキストがないため、次を強制する。

- 表を再現する場合、**行数・列数を先に宣言してから中身を書く**（脱落の検出用）
- 読み取ったすべての数値に `【要確認】` を付す
- 判読できないセルは推測で埋めず「判読不能」と書く
- `number_verified: false` を必ず維持する

全スライド共通:

- 数字は抽出テキストからコピーする。画像から読んだ数字には `【要確認】` を付す
- 確信が持てない背景は書かない。`confidence: low` を設定し「調査が必要な点」として列挙する
- 推測には `【推測】` を付す
- 第215回での委員の発言は議事録未公開のため書かない

### Phase 3: 横断整合

新出用語を検出して `kb/glossary` 未作成分をIssue化、解説中の年月日を `timeline.yaml` と突合、`supports_topics` から `evidence_slides` を逆生成、用語の定義揺れを検出。

### Phase 4: レビュー ★省略不可

**4-a. 機械チェック（`validate.py`）**

- フロントマターのスキーマ検証
- 解説中の数値を、そのページの抽出テキストに現れる数値集合と突合。含まれない数字はフラグ（`text_extractable: false` のページはこの検査を飛ばし、全件を人間レビューに回す）
- 参照キー（`terms` / `supports_topics` / 関連スライド）の解決可否
- 外部URLの死活

**4-b. ファクトチェック**

- 別セッションで、解説Markdownとページ画像だけを渡して事実誤認を検証する。生成時のコンテキストは渡さない（同じ思い込みの再生産を防ぐため）
- **§0.3の7枚は、人が画像と解説を並べて数値を照合する。** ここは自動化しない
- 通過したら `review_status: verified` / `number_verified: true` に更新

### Phase 5: ビルドと配信

```yaml
# .github/workflows/pages.yml（概要）
on:
  push: { branches: [main] }
jobs:
  build:
    steps:
      - uses: actions/checkout@v4
      - name: PDFのキャッシュ            # manifest.yaml の SHA256 をキーにする
        uses: actions/cache@v4
      - run: sudo apt-get install -y poppler-utils webp
      - run: python build/fetch.py --all
      - run: python build/extract.py --all
      - run: python build/build.py --out dist
      - uses: actions/upload-pages-artifact@v3
        with: { path: dist }
  deploy:
    steps:
      - uses: actions/deploy-pages@v4
```

PDFをキャッシュすることで、毎回厚労省サーバーへ取得しにいかずに済む。パブリックリポジトリなのでActionsの分数上限はない。

## 6. 品質ルール

1. 数字は原典からのコピーのみ。計算した場合は式を併記する
2. `【事実】【解釈】【推測】` の3ラベルを本文中で使う。セクション6・7は解釈が中心なのでその旨を明示する
3. **§0.3の7枚は、人が数値を照合するまで `number_verified: false` を維持し、ビューアで警告を出す**
4. 委員の発言は議事録公開後にのみ記載する
5. 引用は最小限にとどめ、要約を基本とする
6. `confidence: low` を恥じない。分からないと記録するほうがシステムとして価値が高い
7. 公開物である以上、誤りは他人に影響する。§4-bを飛ばさない

## 7. 公開に伴う整理 ★v0.3で追加

### 7.1 出典表記

厚労省サイトのコンテンツは公共データ利用規約（第1.0版・PDL1.0）に準拠し、出典明記のうえで複製・公衆送信・翻案ができる。編集・加工した場合はその旨を別途記載し、国が作成したかのような態様で公表しないことが条件となっている。

READMEとビューアのフッタに以下を置く。

```
本サイトは、厚生労働省ウェブサイトで公開されている審議会資料をもとに、
個人が解説を加えて作成したものです。厚生労働省が作成・公認したものではありません。
出典: 第215回社会保障審議会医療保険部会 参考資料「基礎資料」（厚生労働省）
      https://www.mhlw.go.jp/...
```

### 7.2 第三者著作物

PDL1.0は**第三者が権利を持つコンテンツには適用されない**。今回の基礎資料には該当するものが実際に含まれる。

| スライド | 図の権利者 |
|---|---|
| 15（がん患者の5年生存率） | 公益財団法人 がん研究振興財団「がんの統計2025」 |
| 53（消費者物価指数の長期トレンド） | 労働政策研究・研修機構 |
| 54（賃金の長期トレンド） | 労働政策研究・研修機構 |
| 20（妊産婦死亡率・乳児死亡率） | こども家庭審議会資料経由 |

いずれも厚労省が作図したものではなく、他所の図がそのまま貼られている。§1.1で原典PDFと画像をコミットしない方針にしたのはこのためで、リポジトリ自体はこれらを再配布しない。

Pagesで画像を表示するかどうかは `third_party_figure` フラグで制御する。当面は `true` のスライドを画像非表示（出典リンクのみ）で運用し、必要が生じたら判断を変える。設定を1箇所で切り替えられるようにしておくことが目的である。

### 7.3 ライセンス

解説本文は自分の著作物、資料は厚労省のもの。READMEで明確に分ける。

```
LICENSE          : 解説本文・スクリプトに適用（CC BY 4.0 / MIT など）
README の出典節  : 審議会資料の出典と利用条件
```

### 7.4 誤りへの備え

解説には誤りが混入しうる。READMEに以下を明記し、Issueで指摘を受けられるようにする。

- 内容の正確性を保証しないこと
- 一次情報は必ず原典にあたるべきこと
- `number_verified: false` のスライドは未検証であること
