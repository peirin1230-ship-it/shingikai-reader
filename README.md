# shingikai-reader

審議会資料を、スライド1枚ずつ背景を含めて精読・注釈するためのリポジトリ。

**公開サイト: https://peirin1230-ship-it.github.io/shingikai-reader/**

最初の対象は **社会保障審議会 医療保険部会 第215回（令和8年9月11日）** の3資料
（参考資料「基礎資料」83ページ / 資料1 25ページ / 資料2 34ページ = **全142ページ**）。
**142ページすべてに解説がある。** 議事次第（1ページ）を加えて **143枚**。

仕様は [`docs/SPEC.md`](docs/SPEC.md)（v0.3）にある。

---

## このリポジトリが解こうとしている問題

審議会の参考資料は統計と制度説明の集積で、**そのスライドがどの改革論点の論拠として持ち出されるのかがスライド自身には書かれていない。**
第215回の基礎資料72枚にも、論点提示や見直し案のスライドは1枚もない。

そこで本リポジトリは、基礎資料を事実データベースとして構造化し、`supports_topics` で
[`kb/topics.yaml`](kb/topics.yaml) の改革論点への逆引きを張る。

```
基礎資料（事実） ──supports_topics──▶ kb/topics.yaml ◀──evidence── 資料2（論点・対応案）
```

たとえば「70代以降は医療費が高額なのに自己負担は低く抑えられている」という主張を本体資料が
していたとき、その根拠が基礎資料のどのスライドで、出典統計・集計年度・母数が何なのかを
機械的にたどれるようにすることが目的である。

## 何をコミットし、何をコミットしないか ★重要

| 種類 | コミット | 置き場所 |
|---|---|---|
| 解説Markdown | ○ | `councils/{会議体}/{回}/{資料}/pNNN.md` |
| 横断KB（用語・年表・論点） | ○ | `kb/` |
| スクリプト・ワークフロー | ○ | `build/` `.github/` |
| PDFのURL・SHA256・取得日 | ○ | `councils/.../manifest.yaml` |
| 抽出テキスト・OCR結果 | ○ | `work/`（`.txt` と `.json` のみ。約0.5MB） |
| **原典PDF** | **×** | `source/`（gitignore） |
| **スライド画像** | **×** | `images/`（gitignore）。GitHub Pages上にのみ存在する |
| ビルド成果物 | × | `dist/`（gitignore） |

抽出テキストを追跡しているのは、原典が訂正版に差し替えられたときに
**どの数値が変わったかを差分で見られるようにする**ためである。
再生成はできるが、履歴に残しておかないと過去の版との比較ができない。
テキスト以外の中間ファイルは無視する。

原典PDFとスライド画像をコミットしないのは、公開リポジトリでの第三者著作物の再配布を避けるため
（SPEC §7.2）、およびGit履歴に入ったバイナリは削除しても残るためである。
Pagesへのデプロイはブランチにコミットせずアーティファクトを直接ホスティングするため、
この構成なら画像がGit履歴に一切入らない。

原典は `manifest.yaml` のURLとSHA256から誰でも再取得できる。

## 使い方

```bash
make setup     # 依存（poppler-utils, webp, tesseract）の確認
make fetch     # manifest.yaml のURLからPDFを取得しSHA256を検証 → source/
make extract   # PDF → images/ (WebP) + work/ (テキスト・OCR)
make validate  # フロントマター・数値・参照キー・URLの検証
make build     # 解説Markdown + KB → dist/
make serve     # dist/ をローカル配信（http://localhost:8000）
```

`make extract` は、テキスト層から中身を読めないページだけをOCRにかける（`--ocr missing`、既定）。
`--ocr all` で全ページ、`--ocr off` でOCRなし。
**OCR結果は補助であって、原典のテキスト層の代わりにはならない。**
数値の突合には使わず、`number_verified` にも影響しない（精度の実測は
[`docs/pipeline-notes.md`](docs/pipeline-notes.md) §8）。

個別に走らせる場合:

```bash
python3 build/fetch.py    --council hoken --meeting 215
python3 build/extract.py  --council hoken --meeting 215 --document sanko
python3 build/validate.py --all
python3 build/build.py    --out dist
```

`make fetch` はネットワークに出る。`--offline` を付けると既存の `source/` を検証するだけで済む。

### 解説を書くときの補助ツール

```bash
# スライド上の太字を座標付きで出す（§6「事務局がどこを読ませたいか」の材料）
python3 build/inspect.py --council hoken --meeting 215 --page 76 --emphasis

# 表の罫線を検出してセルの結合を調べる（結合を読み違えると転記を誤る）
python3 build/inspect.py --council hoken --meeting 215 --page 77 --grid
```

強調表示と罫線はテキスト層からは分からないので、目視に頼らず機械的に取る。
実際にこれで分かったことは [`docs/pipeline-notes.md`](docs/pipeline-notes.md) にまとめてある。

### 参照している文書

解説が参照する上位の文書（閣議決定・政党間合意・法律）は
[`kb/documents.yaml`](kb/documents.yaml) に、URLとSHA256つきで登録している。
**11件すべて原典を取得済みである。**

最後まで残っていた「**医療法に関する三党合意書**」（令和7年6月6日）は、
政党の公式サイトに掲載が確認できず、二次情報だけを記録していた。
公益社団法人 全日本病院協会が掲載している版を取得し、
SHA256とともに登録した（`santo-goi-2025-06-06`）。
政党の公式配布元ではないため、公式版との同一性は未確認である【要確認】。
PDFはスキャンでテキスト層がなく、本文はスキャン画像を目視で読んだ。
OCR（tesseract）は縦書き・手書き署名の混在で精度が出ず、使えなかった。

### 複数資料の扱い

1つの回に複数の資料があるため、索引は資料ごとに分けている。

```
councils/hoken/215/_meta.yaml            ← 主資料（参考資料）の索引
councils/hoken/215/_meta.shiryo1.yaml    ← 資料1の索引
councils/hoken/215/_meta.shiryo2.yaml    ← 資料2の索引
councils/hoken/215/_meta.shidai.yaml     ← 議事次第の索引
councils/hoken/215/{sanko,shiryo1,shiryo2,shidai}/pNNN.md
```

解説どうしのリンクは資料をまたげる（`../shiryo2/p005.md`）。
`build/validate.py` はリンク先の存在に加えて、
**リンクのラベルが索引上のタイトルと合っているか**も照合する
（ページ番号を取り違えるとリンクは通るのにラベルが別のスライドを指すため）。

## 未検証スライドの扱い ★重要

図表が画像として貼り込まれており `pdftotext` がほぼ空を返すページが、
**参考資料に7枚・資料1に7枚・資料2に1枚**ある。

資料1の7枚（PDF 1・2・6・11・14・15・19）は表紙・目次・中扉3枚と、
画像で貼られた参考資料2枚である。資料2の1枚は表紙だけである。
**数字の密度が高いページを含むのは参考資料のほうで、次の7枚である。**
このうち4枚は、この資料でもっとも数字の密度が高いページである。

| PDFページ | 印刷番号 | タイトル | 抽出文字数 |
|---|---|---|---|
| 21 | 20 | 妊産婦死亡率・乳児死亡率の推移 | 2 |
| 24 | 23 | 医療費全体の伸びの要因〜高齢化率との相関〜 | 65 |
| 25 | 24 | 主要国の医療保障制度（概要） | 44 |
| 28 | 27 | 医療保険制度の体系 | 29 |
| 29 | 28 | 各保険者の比較 | 23 |
| 58 | 57 | 医療費の動向 | 20 |
| 59 | 58 | 医療費の伸び率の要因分解 | 38 |

これらの数値は画像から読み取るしかなく、読み取り誤りが最も起きやすい。
人が原典と突合するまで `number_verified: false` を維持し、ビューアで ⚠ を表示する。
解説中の数値には `【要確認】` が付く。

**★未決の論点**: 上表の「抽出文字数」はバイト数である（日本語1文字＝UTF-8で3バイト）。
文字数で数え直して閾値100を当てると、対象が7枚から**14枚**に増える。
増える7枚（PDF 8・13・14・16・54・55・63）は、テキスト層にタイトルと出典しかなく
グラフの数値が画像の中にあるページで、性質としては同じである。
どちらを採るかは人が決めることなので、`_meta.yaml` の `text_ok` を正としたうえで
両方の判定結果を `work/.../pages.json` に記録し、`extract.py` が食い違いを警告する。
詳細は [`docs/pipeline-notes.md`](docs/pipeline-notes.md) の §1。

## 誤りへの備え

- **内容の正確性は保証しない。** 解説には誤りが混入しうる。
- **一次情報は必ず原典にあたること。** `manifest.yaml` にURLとSHA256がある。
- `number_verified: false` のスライドは、数値が人の目で照合されていない。
- 委員の発言は、議事録が公開されるまで記載しない（第215回の議事録は未公開）。

誤りを見つけた場合は Issue で指摘してほしい。テンプレートを用意している
（`背景が不足している` / `事実誤認の疑い` / `用語未作成`）。
